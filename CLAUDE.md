# CLAUDE.md — Norman Roofing Experts (Roof Leak Repair, Severna Park, MD)

Project architecture and conventions for this repo. Read this before making changes.

## What this project is

A static **Astro** pay-per-call lead-gen site for the micro-niche **roof leak repair** in
**Severna Park, Maryland** (plus Arnold, Pasadena, Millersville, Severn and Glen Burnie). It
was rebuilt on 2026-10-21 from the old broad "roofing in Norman, OK" site; only the domain,
brand name, phone and email carried over. Every CTA is a phone call: no forms. No GMB and no
physical address. Calls go to an independent local roofing provider.

Strategy, keyword data, page plan and design direction: `docs/STRATEGY.md`.
Scope, honesty rules and open questions: `docs/brief.md`.

## Read MEMORY.md first

Before making any change, read **`MEMORY.md`** (repo root, gitignored, local only). It's the
live map of current state: file locations, config values, page inventory, outstanding items
and a log of recent changes. **After completing any change**, update the relevant section(s)
and its "Recent changes" log. If it looks stale versus the code, fix it as part of the task.

## Current stage

**Live since 2026-10-21.** 18 indexable pages + 404: homepage, 8 leak-repair service pages,
5 area pages, about, contact, privacy, terms. `npm run check` passes (build, SEO audit, content
audit). Outstanding items are in `docs/brief.md` §6.

## Stack decisions

- **Astro only.** No React/Vue/Svelte and no CSS framework. Ask before adding a dependency.
- **Content collections** back services and locations. New pages are markdown entries, never
  one-off `.astro` pages. Both collections render at **first-level URLs** through
  `src/pages/[slug].astro`, so file names must be unique across both folders.
- **Service page body order** (markdown): definition → how it works → 8 warning signs
  (`<ul class="sign-list">`) → causes → safe DIY checks (+ Pro tip callout) → the pro visit →
  cost-factor table (`<div class="table-wrap">`) → prevention → when it's an emergency
  (+ Warning callout). FAQs and related links come from frontmatter.
- **Location page body:** why it matters here → top services (H3s) → local checklist →
  questions to ask → nearby areas. 5 FAQs in frontmatter.
- **Static output only.** No SSR, no forms, no server endpoints.

## Design

Navy `#0B2545` + orange `#F97316` (orange only for CTAs and highlights; orange text uses
`--accent-700` for contrast). Sora (headings) + Inter (body), self-hosted via Astro fonts.
Signature visual: the cut-away house SVG in `HeroScene.astro` (homepage).

Service and area pages follow the reference site's section layout (2026-10-21): photo hero
with a "talk to a pro" card, trust strip, then **one full-width section per H2**, styled by
kind (`src/utils/sections.ts` + `ContentSections.astro`): image splits, numbered card grids,
dark warning-sign band, process steps, cost panel, FAQ split, photo cards. The section kind
comes from the H2 wording, so keep the heading patterns when writing new pages.

Photos are original, generated with Grok (Mudassar's X Premium) and live in
`src/assets/photos/`; frontmatter `heroImage`/`image` (+ alt) point at them, and
`src/utils/photos.ts` serves the 3 shared ones. Never use stock photos or competitor images,
and never present a generated photo as a real local job.

## Development

```
npm install
npm run dev            # dev server
npm run build          # production build
npm run check          # build + seo-audit + content-audit: run before any commit
npm run content-audit  # word counts / duplicates / links; rewrites docs/AUDIT.md
```

Content minimums enforced by `content-audit.mjs` (main content only): homepage 2,500,
service 1,500, location 1,000, about 700, contact 350. Each service and location page must
link to `/` once in a paragraph, with an anchor no other page uses more than once (rotation
table: `docs/STRATEGY.md` §6).

## Working conventions

- Honesty rules in `docs/brief.md` §2 are hard rules: no address, LocalBusiness schema,
  reviews, ratings, prices, years in business, licences, response times or 24/7 claims.
- Keep every page leak-specific. General roofing (replacement, gutters, commercial) is out of
  scope for this micro-niche.
- Real place names only; local facts only if widely known and true.
- Keep `docs/` in sync when decisions change.
